# Architecture

The vector notebook is authoritative. `InkStore` publishes immutable snapshots plus changed/deleted stroke and object IDs, old/new bounds, document generation and revision. Transactions share unchanged frozen vectors; mask lookup is indexed once per changed mask collection. Undo/redo restore canonical content; clear and replacement invalidate worker generations.

Four canvases separate committed ink, active gestures, computed answers and annotations. Pointer events append samples without React renders or ML. Animation frames paint shared pressure-aware geometry. Committed layers retain pixels, clip repaint to damaged device rectangles and redraw intersecting content with masks; camera, appearance and backing-size changes rebuild only visible content. Targeted per-stroke masks preserve partial erasure, alpha and later ink.

`EquationTracker` owns cached rectangles and stroke→equation membership. After initial grouping, change events select touched owners plus nearby candidates from old/new bounds. Only candidate vectors/masks cross the worker boundary. Reconciliation preserves groups whose canonical content is unchanged, reuses identities for edits, and retires merged/split-away groups. Nearby candidates are not automatically dirty. Identity derives from source ink at first grouping and remains stable during reconciliation.

A dedicated worker groups lines and glyphs, applies the shared erasure/geometry renderer, rasterizes verified RGB tensors and runs the pinned pretrained CNN through ORT WASM. At most four segmentation candidates share the effective-input prediction cache. A speculative split does not withhold a uniquely confident plausible reading; conflicting confident readings, low model confidence and unresolved geometry remain uncertain. The symbol cache is bounded and tied to geometry, masks, model hash and preprocessing version. The scheduler coalesces queued edits per equation and guards responses per request, equation revision and document generation. Work already running can finish; obsolete replies are rejected. An individual equation failure preserves unrelated answers and continues the queue; worker initialization and transport failures still require a worker restart.

`ProjectionStore` combines recognized ink with explicitly marked typed-math annotations in spatial notebook order. `NotebookEvaluator` caches parsed ASTs, normalized text, outcomes and diagnostics. Each dependency records the exact preceding variable definition and its current outcome. Rebinding, movement and deleted/pending definitions update consumers’ contexts; unrelated expressions reuse their cached results and stable projections. A pending edited definition blocks its consumers without rerecognizing their handwriting.

`CalculationHistory` holds one completed record per live equation. Content/result changes move it to the front; pending, invalid or deleted equations remove its record. Current follows the changed source equation. Clear, import and notebook changes reconcile derived state. History regenerates from canonical ink/typed math after reload; exact completion timestamps are not persisted.

Named notebook snapshots save to IndexedDB through a debounced serialized write queue. An import validates the schema, replaces the active notebook and clears session undo history. Offline Cache API assets are independent of notebook persistence: the production build creates a content-versioned asset list, and Offline ready requires both cache completion and model warm-up. Older caches remain to avoid mixing assets in open tabs; automatic cache reclamation is a known storage limitation.
