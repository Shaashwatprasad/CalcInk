# Feature preservation and product action evidence

Phase 0 audit on `codex/calcink-v2`, inherited baseline `e5e48beb3a698282cc7e0ae14dd5f27375b89a44` plus the preserved user changes. Source identity is the actual source hash in each track report; a dirty working tree is not an exact commit. This tester read all 2,689 lines of the master specification, including Appendices A and B, and inspected the existing application, renderer, persistence and browser tests before writing this inventory.

The master specification is authoritative for V2. Existing instructions that defer x or highlighter are superseded. Existing geometry, mask semantics, arithmetic, JSON imports/exports, storage and worker assets must survive the migration. The only approved deliberate UI removal is the visible AST/separate parser presentation. No such AST UI exists in the inspected source.

The authoritative machine-readable inventory is [feature-actions.json](../tests/registry/feature-actions.json). It currently declares **41 features (38 required, 3 conditional/optional), 125 action/state entries and all original R01–R12 requirements**. Twenty-two entries are exposed by the inspected baseline. Declaration and test-ID linkage are not accepted behavior. All `latestResult` values begin PENDING; current-source Playwright reports are combined with the registry by the checker without mutating the registry or invalidating their own source hash.

A feature with no implementation path is proposed V2 work. `partial` means source implements only part of the final requirement. `implemented_unverified` means source exists, with fresh integrated-source execution and independent review still required. Figma node IDs and supplied styling are targets; this product tester did not independently fetch Figma and does not claim design parity.

The original PS R01–R12 mappings are retained in `docs/REQUIREMENTS.md` and the registry. Product tests supplement the ML track and parser/worker unit tests; a passing UI arithmetic fixture does not establish all-class classifier accuracy, safe-parser boundary coverage, physical device latency or a public demo. It remains explicitly unmapped in the product registry gate rather than being counted as passing.

The registry checker validates schema, executable case linkage and explicit baseline assertion anchors, exiting zero when the inventory itself is valid. Its `BLOCKED_WITH_EVIDENCE` status still lists missing/unimplemented/unverified behavior. `--gate` exits 2 for that incomplete acceptance state. Exit 1 means a broken registry/schema. Pass a Playwright JSON `--report=...` and actual `--identity-report=...` to overlay exact-source results; stale identities, skipped cases, failures and retries never count as passes. The supervisor track runner handles these paths and identity hashes.

The required workflows carry `@v2-required`; the root-owned configuration excludes them only for the explicitly scoped Phase 0 available-check run. Release enables them. They are neither skipped nor expected-failure tests. Missing controls and behavior cause actual failures when enabled. The registry reports **125 declared links, 20 meaningful baseline mappings and 105 uncovered actions (62 planned integration cases, 43 missing action-specific assertions)** out of 125 actions. A declared link never counts as accepted coverage. Explicit trigger/assertion anchors are validated against the owning executable case, with independent review still required. The registry explicitly lists the missing behavior cases; their broader workflow links are not a claim that touch/pinch, resizing, every feedback state or every cancel path is already tested. Pressure ink, touch/pinch, selection resize, text editing, Clear Escape, multiplication correction, most feedback states, zoom transforms/fit, rendered paper settings, highlighter opacity and object save/reload need complete cases before final acceptance.

The independent browser guards fail unexpected page/console errors and failed JS/WASM/model/manifest requests. Expected model-load faults are narrowly recorded in the fault case. Tests use isolated Playwright contexts and actual UI events, import file selection, downloaded JSON and read-only canvas/export inspection. They never call InkStore, the evaluator or production application internals to carry out a claimed UI action. Synthetic arithmetic vectors are wiring regressions, not human handwriting samples. Emulated input is not physical stylus/touch evidence.

The runtime control discovery case (`PROD-B13`) compares the accessible labels of visible buttons, links and sliders with the version-controlled registry. It catches new controls in the discovered baseline state but is not exhaustive menu/gesture discovery. Manual/source inventory discovered conditional Retry, notifications, file chooser, shortcuts, cancellation and responsive replacements. Future implementation must update this registry and add meaningful assertion coverage whenever it exposes more controls.

Known baseline defects and pending acceptance:

- Clear mutates immediately without confirmation. The working clear/history operation remains preserved by PROD-B12; PROD-V06 independently requires confirmation before mutation.
- The large intro/footer/export/feedback regions leave the writing area at a fixed 540 px; PROD-D03 records actual paper/viewport fractions and overflow at every requested width. Its observational pass does not accept full-viewport paper.
- Help is hidden below 760 CSS px with no replacement. All V2 selection/annotation/Hand/theme/paper menus and mobile drawer/sheets are absent in the baseline.
- Current 16-class recognition includes multiplication, not an independent letter x; the arithmetic-only evaluator rejects x. PROD-V12 is an actual crossing-ink assignment/use acceptance case, with user-assisted correction explicitly distinct from automatic recognition. Assignment editing/erase/history/isolation and all nine states require additional complete cases.
- Recognition returned top-k in the baseline worker, while product feedback concatenates top-1. Explicit corrections, adaptive grouping and structural fraction evidence remain pending.
- P1 source repair now keeps the projection renderer mounted and replays the active joined path; PROD-D01 and PROD-D02 assert alpha parity and zero unchanged projection resets through real browser drawing/inference. Raw long-stroke rAF intervals and ink samples are attached, without a universal 60 FPS claim.
- Physical mouse/stylus/touch quality, slower hardware, writer-disjoint corpus, all-class accuracy, schema V2 migration/object eligibility, corrupted IndexedDB recovery/storage failure and two-version offline updates remain independent evidence needs. No fabricated dataset or hardware result is used.

The three optional/conditional entries (plotting, practical pages/PDF/image export, optional audio/haptics) are not exposed or implemented by baseline source. They remain backlog extension boundaries rather than delivered features. Broader identifiers/functions are unsupported; x is mandatory and must not be relabelled optional.
